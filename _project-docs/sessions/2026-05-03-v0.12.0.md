# Session — v0.12.0
**Date:** 2026-05-03
**Version:** 0.11.0 → 0.12.0

## What We Did
- Audited the live DPN FastAPI server source at `github.com/catnipp9/transistors-thermal-dpn-ai/blob/main/api/main.py`. Found that `lib/dpnApi.ts` had the wrong response shape: prediction enum was `"Diabetic"/"Control"` (actually `"DPN Positive"/"DPN Negative"/"Unknown"`), confidences were treated as 0–1 (actually percentages 0–100), and a number of fields were missing entirely (`is_valid_foot`, `rejection_reason`, per-foot `regions`, sub-model probabilities, `fusion_method`, full `AsymmetryResult`).
- Updated `lib/dpnApi.ts` types to the real contract.
- Migrated the DB so the API response shape lines up cleanly with `classification_results`. Dropped four unused per-region columns from `thermal_captures` and added the matching jsonb + numeric fields on the results table. Detail in `supabase-changes.md`.
- Built `components/thermal/DpnResultView.tsx` to render the full result (verdict, per-foot card with probability bar + YOLO/sklearn breakdown + region temps, asymmetry block with per-angiosome bars, diagnosis factors, rejection branch).
- Rewrote `app/(clinic)/assess-bundle.tsx` as the dedicated DPN assessment screen. Now hydrates from the stored row when revisited, otherwise runs the full pipeline and persists every new field.
- Replaced the inline result block in `ImportCaptureScreen` with the shared `DpnResultView` (also fixing the 8950% percentage bug it had).
- Added an "Analyzed / Not Analyzed" pill and matching green/amber border to `SessionCard` (used by both clinic and patient history) and to the bundle-detail header strip.
